## 1. ゴール仕様（GT Modern の Pipe Placement 準拠）

GT Modern 公式ドキュメントの仕様は次の通り。

- 置いただけのパイプ／ケーブルは、デフォルトでは隣接ブロックのどれにも接続しない
- 機械や他のパイプに対して Shift（スニーク）しながら右クリックで設置した場合だけ、
  その相手に接続して置かれる
- 接続の追加・解除はレンチで面ごとに行う
- シャッター（Shift+右クリック）でその面を出力専用にできる ※Mek 側の PUSH/PULL が相当するので本 Mod では扱わない

これを Mek の語彙に翻訳すると:

| # | 仕様 | Mek での実現 |
|---|------|--------------|
| S1 | 設置直後のトランスミッターは全 6 面が切断状態 | 全面の `ConnectionType` を `NONE` にして置く |
| S2 | 意図して向けた相手にだけ接続して置かれる | 同ジャンルのパイプへ向けた設置は自動で接続。それ以外はスニーク時だけ、クリックしたブロックに面する側を `NORMAL` で開く（§3） |
| S3 | 隣に後から置かれた等の理由で、切断した面が勝手に再接続しない | S1 の帰結として自動で満たされる（§2 の相互合意チェック参照） |
| S4 | 面ごとの接続／切断は手動でいつでも変更できる | コンフィグレーターのガイドで `NONE ⇄ NORMAL` をトグル（§5） |
| S5 | 既存ワールド・既存ネットワークには影響しない | 設置イベントでだけ介入する。ロード時には何もしない |

対象トランスミッター（全て `TileEntityTransmitter` のサブクラスで一括で効く）:

- ユニバーサルケーブル（エネルギー）
- メカニカルパイプ（流体）
- 加圧チューブ（ケミカル）
- 熱伝導体（熱）
- ロジスティカル・トランスポーター類（アイテム。通常／分岐／制限を含む）

## 2. なぜ小さく作れるか（本体ソースで確認した事実）

1. **接続状態は面ごとの `ConnectionType` が全て。**
   `Transmitter#connectionTypes`（Direction 順の 6 要素配列）が唯一の実体で、
   初期値が全面 `NORMAL` なのが自動接続の原因そのもの。
   値の読み書きは公開 API `getConnectionTypeRaw` / `setConnectionTypeRaw` でできる。

2. **トランスミッター同士の接続は、既に「相互合意制」。**
   `Transmitter#canConnectMutual` は、自分の面が `NONE` でないことに加えて、
   相手トランスミッターの反対面が `canConnect` であることを要求する。
   つまり片側が `NONE` なら、相手側が `NORMAL` でもネットワークは繋がらない。
   → 勝手な再接続（塩水と水が混ざる Mek 本家 Issue #6582 型の事故）は、
     「置いた面を `NONE` のままにしておく」だけで構造的に防げる。

3. **ネットワークへの参加は設置直後ではなくサーバーティックで処理される。**
   設置されたトランスミッターは `TransmitterNetworkRegistry` の孤児（orphan）
   として登録され、実際のネットワーク割り当ては `ServerTickEvent` 内の
   `assignOrphans` で行われる。
   → 設置イベント（同一アクション内、ティックより前）で `ConnectionType` を
     書き換えれば、誤ったネットワークが一度も形成されない。チラつきも転送も起きない。

4. **コンフィグレーターの変更手順が、そのまま流用できる。**
   本体 `TileEntityTransmitter#onSneakRightClick` は
   `setConnectionTypeRaw` → `refreshConnections()` → `notifyTileChange()` →
   `sendUpdatePacket()` の順で変更を反映している。本 Mod の設置後処理も
   この手順に揃えれば、同期・見た目・ネットワーク分割の面倒は本体が見てくれる。

5. **1.20.x も同構造。** `canConnectMutual`、生の接続タイプ API、コンフィグレーターの
   処理手順は 1.20.x / 1.21.x で同一。イベント名と登録まわりだけがローダー差分。

## 3. 設置時の接続決定ルール

設置アクションから「クリックしたブロックの位置」と「クリックした面」をサーバー側で記録し、
設置されたトランスミッターについて次を決める。**同ジャンルのパイプへ向けた設置だけは
スニーク不要で接続**し、それ以外はスニーク時だけ接続する（全面 `NONE` が既定）。

```
clickedPos / clickedFace = プレイヤーが右クリックしたブロックと面
placedPos = clickedPos.relative(clickedFace)
openSide  = clickedFace.getOpposite()   // 新しいパイプから見た、相手の方向
```

| クリック相手 | スニークなし | スニークあり |
|--------------|--------------|--------------|
| 同ジャンルのトランスミッター | `openSide` を `NORMAL` で開く（`connectPlacedPipe`）。相手の反対面が `NONE` なら `NORMAL` で開く（対称オープン、§4） | 同左 |
| 異ジャンルのトランスミッター | 全面 `NONE` | `openSide` を `NORMAL` で開く。相手の反対面が `NONE` なら `NORMAL` で開く（対称オープン、§4） |
| 搬入出可能なブロック（機械・タンク・他 Mod のケーブル等、対象の TransmissionType を受け付けるもの） | 全面 `NONE` | `openSide` を `NORMAL` で開く。相手側の面状態は変更しない |
| それ以外（地面・壁・通常ブロック） | 全面 `NONE` | 全面 `NONE`（相手が受け付けない） |
| プレイヤー以外による設置（ディスペンサー、`/setblock`、構造物、他 Mod の自動設置） | config `nonPlayerPlacement` に従う。初期値は「全面 `NONE`」ではなく **バニラ挙動のまま（全面 NORMAL）** を推奨。自動建築系を壊さないため | 同左（スニーク状態が無い） |

補足ルール:

- スニーク状態はサーバー側の `Player#isShiftKeyDown()` で読む。クライアントが送る
  `ServerboundPlayerCommandPacket` の PRESS/RELEASE_SHIFT_KEY によりサーバー側の
  プレイヤー状態が更新されるため、設置イベントの時点で正しい値が取れる。
- `connectClickedSide=false` の場合、スニークしていても何も開かない（全面 `NONE`）。
  `connectPlacedPipe=false` の場合、同ジャンルのパイプへ向けた設置でも開かない。
  `openCounterpartSide` は設置・接続変更の両方の対称オープンを制御する。
- クリック相手の判定は「その面にその TransmissionType の capability / acceptor が
  あるか」で行う。本体の acceptor 判定（`isValidAcceptor` 相当）に寄せ、
  独自の対応表は持たない。
- トランスポーターの色違い・ソーター背面など、本体固有の接続可否
  （`LogisticalTransporterBase` 等のオーバーライド）は本体判定が上書きする。
  本 Mod は生の `ConnectionType` しか触らないので、それらと競合しない。
- 設置の記録はサーバー側で `PlayerInteractEvent.RightClickBlock` を拾い、
  プレイヤー UUID → (位置, 面, 手持ちのトランスミッター, ゲーム時間) を保持。
  `BlockEvent.EntityPlaceEvent` で placedPos が一致したものだけ消費する。
  記録の有効期限は数ティック。一致しない設置（コマンド等）は「プレイヤー以外」の扱い。
- 通常の設置はバニラの右クリック処理に任せ、設置イベント後に接続状態だけを書き換える。
  パイプ所持時のガイド設置だけは、入力段階でクリックを横取りしてサーバー側で
  `ItemStack#useOn` を 1 回実行する（§12）。

## 4. 対称オープン（相手側も開く）の要否

新しいパイプ A を既存パイプ B に向けて置くとき、B の A 側の面は
（B が本 Mod で置かれたものなら）`NONE` になっている。
相互合意制（§2-2）により、A 側だけ開いても繋がらない。

GT / Advanced Pipez Utilities の挙動に合わせ、**同ジャンルのパイプへ向けて置く行為
（またはスニークして向けて置く行為）そのものを接続の意思表示とみなし、B の反対面も
`NORMAL` に開く**。
プレイヤーが B 側を意図的に閉じた場合でも、「A を B に向けて置いた」時点で
その意思は上書きされる。これは Pipez 版の "creates a connection only on
the side you clicked" と同じ解釈で、想定外ではなく明示操作なので許容する。
config で無効化も可能にする（`openCounterpartSide=false` の場合、A 側だけ開き、
繋げたければ B 側をコンフィグレーターで開く必要がある、厳密 GT 寄り）。
同じ対称オープンは、コンフィグレーターで面を接続したときにも行う（§5）。

## 5. 手動での接続変更（コンフィグレーター）

本 Mod のガイド表示中は、スニーク不要の右クリック（入力段階フック）で
**接続/切断の 2 択**をトグルする。`NONE` なら `NORMAL`、それ以外なら `NONE`。
Mekanism 本体の `PUSH`/`PULL` は「接続」として扱うため、クリックで切断され、
再接続すると `NORMAL` に戻る（方向設定は復元しない）。GT のレンチと同じ文法。
操作ツールはコンフィグレーターで確定とする。**専用アイテムは追加しない**
（2026-11-20 ユーザー決定。レシピ・所持枠・他 Mod との工具競合を増やさないため）。

### 5.1 接続変更時のガイド表示

土台として、本体には既存のガイド表示がある:

- コンフィグレーター所持時、本体の選択ボックスは狙った接続パーツ（腕／中心）単位に
  切り替わる（`BlockTransmitter#getShape` の既存挙動）
- 接続中の面は腕の形状で、切断中の面は腕が無いことで判別できる
- 変更直後、アクションバーに新しい接続タイプが表示される（本体の既存メッセージ）

ただし弱点がある。切断中（NONE）の面には腕が無いので狙えず、
中心キューブのその方向の面をクリックして切り替える本体のフォールバックは発見しにくい。
本 Mod では設置直後のパイプが全面 NONE になるため、この弱点が常時発生する。
よって本 Mod ではガイド表示を自前で実装し、次を仕様とする:

**表示条件**: 次のいずれか。

- コンフィグレーターをメインハンドに持ち、Configurate 系モードでトランスミッターを
  見ている間（接続/切断のトグル用）
- 同ジャンルのトランスミッターのアイテムをメインハンドに持ち、同ジャンルの
  トランスミッターを見ている間（設置ガイド用、§12）

どちらでもないときは表示しない。トランスミッターのアイテムを持っていても
ジャンルが違えば表示しない。

**表示内容（GT 式の面グリッド）**: 見ている面の上に 3x3 グリッドを半透明で重ねる。
セルの対応は GT の古典ルール通り、中央 = 見ている面、上下左右の辺セル = その隣接面、
四隅 = 反対側の面。これにより、1 つの面を見たまま 6 面全部を選べる。

**セルの表示（2 状態）**: セルに背景色は付けない（全状態共通、2026-11-20 ユーザー指示）。
コンフィグレーターモードでは接続 = 接続アイコン、切断 = 切断アイコン。
設置ガイドモードでは、隣が空気の面だけ接続アイコンを出し、それ以外は何も出さない。
強調は GT 本家と同じく不透明度で行う:
今狙っているセルのアイコンだけ 100%、他は 27%。白い枠線は引かない
（2026-11-20 ユーザー指示）。

**本家準拠（2026-11-20 ユーザー指示で確定）**: 表示要素は GT 本家にあるものだけに
限る。グリッド線・アイコン・不透明度による強調のみで、次は入れない:
クロスヘア付近の HUD テキスト、切断面のゴースト腕、実効状態ドット、
次値プレビューのドット（いずれも初期案で足した独自要素、本家には無い）。
変更後のフィードバックは本体コンフィグレーターの既存メッセージそのままを使う。

**実装メモ（クライアントのみ）**:

- セル判定は Mek の接続パーツ用ボックスを使わない。NONE の面にはボックスが
  無いため。見ている面とヒット位置の UV から 3x3 セルを純粋に計算する
- 描画はハイライト描画イベントで、面から僅かに浮かせた半透明クアッドと
  グリッド線のみ。セルの白枠は使わない。バニラのアウトラインはガイド表示中は置き換える
- トランスミッターは細いので、ガイド用ツール所持時は当たり判定の見た目を
  フルブロックに広げて狙いやすくする（Advanced Pipez Utilities と同じ手法）

**実装メモ（追記・2026-11-21）**:

- **狙い判定はクライアント専用のフルブロックレイキャスト**。トランスミッターの
  選択形状（0.5 幅の芯）は変更しない。クライアント側で `ClipContext` の
  shape getter を差し替え、トランスミッターのブロックだけフルブロック形状で
  視線をクリップする（それ以外は通常のアウトライン形状）。ガイド表示と
  コンフィグレーター循環は同じ展開ヒットを使うため、断面の 9 セルすべてを狙える。
  判定は「最近ヒット優先」で、手前に通常ブロックがあればそちらが勝つ
  （壁の向こうのトランスミッターは対象にしない）。
- **循環の入力（2026-11-26 修正）**: 右クリックは `RightClickBlock` ではなく
  入力段階（`InputEvent.InteractionKeyMappingTriggered`）で拾う。バニラの
  `RightClickBlock` はクロスヘアがブロックに当たっているときしか発火しないため、
  細いパイプの外側セルを狙うと（バニラのヒットが MISS になり）循環できなかった。
  入力段階でキャンセルすれば use-on パケット自体が送られないので、サーバーは
  バニラ設置も Mekanism 自身のコンフィグレーター動作も実行しない。スニークは
  不要で、狙いは拡張ヒットのホバーセル面を使う。ガイドと循環はコンフィグレーターの
  Configurate 系モードでのみ有効（WRENCH などのモードは従来の挙動を保つ）。
- **副作用（意図したトレードオフ）**: 対象トランスミッター上では、コンフィグレーターの
  素の右クリックが「レッドストーン感知のトグル」ではなく「ホバーセルの循環」になる。
  GT のレンチと同じ解釈（右クリック＝接続変更）で、レッドストーン感知は
  ガイド表示中は使わない。1 押下＝1 循環に固定し、押しっぱなしの連続循環はしない。
- **v0.2.0 で削除し、v0.3.0 で戻したもの**: 設置ガイドモード
  （`GuideTarget.Mode.PLACEMENT`）とセル選択設置。v0.3.0 では入力段階フックで
  クリックを横取りするため、二重設置ガード（`GuardRecord`）は不要。
  `PlaceTransmitterPayload` は `PlaceTransmitterPayload`（v0.3.0 で再追加）として
  復活した。§12 を参照。

### 5.2 切り替え（通常／搬入／搬出／遮断）とガイドの整合性

> **v0.3.0 で廃止**: 接続変更は `NONE ⇄ NORMAL` の 2 択になった。以下の
> PUSH/PULL を含む 4 状態の議論は歴史的記録として残す。ガイドは PUSH/PULL を
> 「接続」として表示し、クリックで `NONE` にする。方向矢印・色分け・
> 次値プレビューは使わない。

4 状態の切り替えとガイド表示が食い違わないよう、次の規則で統一する。
前提として本体ソースで確認した事実が 2 つある:

- 循環順は本体 enum の順で固定: 通常（NORMAL）→ 搬入（PUSH）→ 搬出（PULL）
  → 遮断（NONE）→ 通常…。`getNext()` がこの順で、ガイド側で変えない
- 「設定値」と「実効値」は別物。本体の実効値 `getConnectionType(side)` は
  未接続の面では常に遮断になり、パイプ同士の接続面では設定が搬入／搬出でも
  常に通常として描画・動作する。ガイドが設定値だけを見せると腕モデルと食い違う

用語の対応（本体の日本語表示は相手ブロック基準の命名なので注意）:

| 設定値 | 本体表示 | 色 | パイプから見た方向 |
|--------|----------|----|--------------------|
| NORMAL | 通常 | オレンジ | 双方向 |
| PUSH | 搬入 | 明るい緑 | 出力（パイプ → 相手へ出す） |
| PULL | 搬出 | 黄 | 入力（相手 → パイプへ入れる） |
| NONE | 遮断 | 白 | なし |

整合性ルール:

1. **色は設定値と 1 対 1 で固定。** 本体定義色はテキスト表示（ホバー表示と
   アクションバー）の色として使う。セルには背景色を付けない。
   アイコン周囲の放射マークの色も
   状態ごとに差し替える: 通常 = 本家通り緑、搬入 = 青、搬出 = 黄
   （2026-11-20 ユーザー指示）。他の意味に色を使い回さない
2. ~~実効状態ドット~~ → 削除（2026-11-20、本家準拠のため）。
   実効状態の追加表示はしない。アイコンは設定値で選ぶ
3. **方向は小さな三角形で補う。** 16x16 アイコン内に収まる 4x4 px 程度の
   白い三角形を、背景なしでアイコンの中央に重ねる（ベクター調の大きな矢印にしない）。
   搬入は面の中心から外側へ向かう向き、搬出は面の中央へ向かう向き。
   通常と遮断には付けない（GT のシャッター矢印と同じ発想で、
   向きの基準は「移送が許可される方向」）
4. ~~ホバー表示（HUD テキスト）~~ → 削除（2026-11-20、本家準拠のため）。
   変更後のフィードバックは本体の既存メッセージそのまま
5. ~~次値プレビュー~~ → 削除（2026-11-20、本家準拠のため）。
   循環順そのものは本体の順を変えない
6. **ガイドは独自の状態を持たない。** 描画のたびにクライアント側タイルの
   設定値（`getConnectionTypeRaw`）と実効値（`getConnectionType`）を読むだけにする。
   設定値は本体の更新パケットで同期されるので、クリックした瞬間に
   セルの色が変わり、本体の腕モデルとも常に一致する

### 5.3 GT 本家のガイドアイコンとの整合性

> **v0.3.0 で 2 状態に統一**: 以下の PUSH/PULL 対応表は歴史的記録。実装は
> 接続 = `tool_pipe_connect`、切断 = `tool_pipe_block` の 2 アイコンだけを使う。

GT Modern 本体のソース（`BlockHighlightRenderer` / `PipeBlockEntity#sideTips` /

## 6. 実装方式

**イベント方式（Mixin なし）を本命とする。**

理由: 接続状態の読み書き・反映手順が全て公開 API で揃っており（§2-1, 2-4）、
本体のティック処理より前に割り込める（§2-3）。Mixin が無いので
Mekanism のマイナー更新で壊れにくく、1.20.1 Forge でも追加ライブラリ不要。

処理の流れ（サーバー側）:

1. `RightClickBlock` でクリック記録（位置・面）を保存
2. `EntityPlaceEvent` で設置ブロックが `BlockTransmitter` か確認
3. タイルを取得し、プレイヤーのスニーク状態と §3 のルールで 6 面の目標値を決める
4. 全面を `setConnectionTypeRaw` で目標値に設定
   （初期値 NORMAL から落とす形。スニーク設置時のみ openSide と対称オープン分だけ NORMAL）
5. 対象タイルと相手タイル（対称オープン時）に本体手順で反映:
   `refreshConnections()` → `notifyTileChange()` → `sendUpdatePacket()`
6. クリック記録を消費

フォールバック（実機検証でイベント方式が間に合わないと判明した場合のみ）:

- Mixin で `TransmitterNetworkRegistry.registerOrphanTransmitter` を遅延させる、または
- Mixin で `TileEntityTransmitter` の設置直後フックに「新規設置フラグ
  （NBT からロードされていない）」を見て初期値を差し替える。
  ロード時に全面 NONE 化して既存ワールドを壊す事故だけは絶対に避けること。

### ローダー差分

| 項目 | 1.21.1 NeoForge | 1.20.1 Forge |
|------|-----------------|--------------|
| 設置イベント | `BlockEvent.EntityPlaceEvent`（NeoForge） | 同名（Forge） |
| 右クリック記録 | `PlayerInteractEvent.RightClickBlock` | 同名 |
| capability 判定 | NeoForge Capabilities | Forge Capabilities |
| Mixin 要否 | 不要（想定） | 不要（想定） |

共通ロジック（ルール判定と面の設定手順）は loader 非依存の 1 クラスに寄せ、
イベント受け口だけを各ローダー側に置く。

### config（初期案）

```toml

enableFluid = true         # メカニカルパイプ
```

## 7. 検証計画（実機確認を必須とする項目）

過去の教訓として、計算・コード読みだけで「直った」と言わない。以下を実機で確認する。

1. **基本**: スニークせずにケーブルを普通のブロックへ置く → 全面 NONE で隣接ブロックに
   繋がらない。スニークしてエネルギーキューブに向けて置く → その面だけ接続。
   隣の発電機側は繋がらず、発電機から給電されないこと。
2. **混流事故の再現テスト**（本家 Issue #6582）: 塩水ラインと水ラインを隣接させ、
   橋渡しになる位置にパイプを置いても両ラインが接続しないこと。
3. **パイプ同士の継続設置**: 同ジャンルの既存パイプをスニークなしでクリックして伸ばす →
   クリックした面で両側が開き、ネットワークが 1 つになること。
4. **手動再接続**: コンフィグレーターで接続 → クリックで NONE → もう一度クリックで
   NORMAL に戻り、繋がること。PUSH/PULL の面をクリックした場合も NONE になること。
5. **切断の保持**: パイプを 1 本抜いても、残りのパイプの面設定が変わらないこと。
   別のパイプを横に置いても、閉じた面が再接続しないこと。
6. **セーブ／ロード**: 面設定が NBT に保存され、ワールド再読込後も維持されること。
   **ロード時に全面 NONE 化しないこと**（最重要の退行テスト）。
7. **チャンク跨ぎ**: アンロード／再ロードで設定とネットワークが壊れないこと。
8. **トランスポーター特例**: 色違いトランスポーター同士が繋がらない、
   ソーター背面に繋がらない等の本体ルールが従来通り効くこと。
9. **プレイヤー以外**: `/setblock` や構造物で置かれたパイプが config 通りの
   挙動（初期値ではバニラ通り全面接続）になること。
10. **専用サーバー**: クライアント側の見た目（接続形状）がサーバー状態と
    一致すること。設置直後の 1 ティックで誤表示しないこと。
11. **設置ガイド**: 同ジャンルのパイプを手に持って同ジャンルのパイプを見る →
    3x3 グリッドが出て、隣が空気の面だけ接続アイコンになること。ジャンルが違うと
    出ないこと。アイコンの面をクリックするとその面へ設置され、接続状態になること。
    狙った面が埋まっている場合はクリックした面へフォールバックすること。
12. **対称オープン（手動）**: 片側が NONE のパイプ同士で、コンフィグレーターにより
    片側を接続 → 相手側の対向面も NORMAL になり、ネットワークが繋がること。
    切断は相手側の設定を変えないこと。
13. **2 状態表示**: PUSH/PULL の面が接続アイコンで表示され、クリックで NONE に
    なること。方向矢印が出ないこと。

### 12.1 パイプ所持時の設置ガイド

- 表示条件は「同ジャンルのトランスミッターのアイテムをメインハンドに持ち、
  同ジャンルのトランスミッターを見ている」。ジャンル判定は
  `TransmissionType` の共通部分で行う（`TransmitterItems#sameGenre`）。
- グリッドはコンフィグレーター時と同じ 3x3。アイコンは GT の
  `BlockHighlightRenderer` と同じく、`level.isEmptyBlock(pos.relative(side))`
  が真の面（＝設置できる空き面）にだけ接続アイコンを出す。
- クリックは入力段階（`InputEvent.InteractionKeyMappingTriggered`）で横取りし、
  `PlaceTransmitterPayload(targetPos, chosenSide, clickedFace)` を送る。
  サーバーの `TransmitterPlacementLogic#placeSelected` が
  `BlockPlaceContext` を作って `ItemStack#useOn` を 1 回実行する。
  入力段階でキャンセルするため、バニラの use-on パケットは送られず、
  v0.1.x の二重設置ガード（`GuardRecord`）は不要。
- 設置位置は GT と同じ: 選んだセルの隣が空気ならその面、
  埋まっていれば実際に見ていた面へフォールバック。
- 設置後の接続は通常の `BlockEvent.EntityPlaceEvent` 経路に任せる。
  同ジャンルのパイプへ向けた設置は `connectPlacedPipe` でスニーク不要に接続し、
  相手側の対向面も `openCounterpartSide` で開く。

### 12.2 2 状態の接続変更

- コンフィグレーターのガイドクリックは `NONE ⇄ NORMAL` のトグル。
  `PUSH`/`PULL` は「接続」として扱い、クリックで `NONE` にする。
- 4 状態循環（`getNext()`）、PUSH/PULL 専用アイコン、方向矢印
  （`tool_triangle`）は描画・処理とも使わない。テクスチャ資産は残している。
- 接続時、隣が互換トランスミッターで対向面が `NONE` なら `NORMAL` に開く
  （`SideCycleLogic#openCounterpart`）。切断は相手側へ波及させない。
